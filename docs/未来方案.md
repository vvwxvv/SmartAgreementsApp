## 3. signedIp 隐私

现状：签署 IP 明文存储，并在 PDF / 管理端展示；**签署页只显示自己的 IP**（2026-11-23 已收紧）。

目标：明确保存期限与用途；可选加密/令牌化；隐私说明写到签署页。

验收：文档写明保留期；删除/匿名化流程可执行；不泄露到公开页面。

## 4. 生产数据库与索引路径

**已完成（2026-11-22 / 11-23 复核）**：`scripts/init-indexes-prod.mjs` + `npm run db:indexes:prod`；
默认 dry-run，`--apply --confirm=<db>` 执行后校验唯一索引；测试见 `tests/index-prod-mongo.test.mjs`。

仍需：在目标生产库执行一次并保存输出；确认 `prestart` 检查通过。

## 5. 导入工具的生产就绪

现状：逻辑与 DB 测试已补，但 `@prisma/client` 在本机生成不了（引擎下载被阻断），真实导入链路未跑通。

目标：允许 Prisma 安装脚本或预置引擎；在快照库跑一次 `db push` 并保存 stdout/stderr；
用真实数据跑 dry-run → `--apply` → 校验计数。

验收：快照库导入后计数一致、互引闭合、`Counter` 只升不降；失败路径有非 0 退出。

## 6. 签署端点限流与幂等

**已完成（2026-11-23）**：`src/lib/rateLimit.js` 固定窗口计数，签署 20 次/分（IP+token）、
核验 60 次/分（IP）；超限 `429 + Retry-After`；`RATE_LIMIT_DISABLED=1` 仅测试用；
重复提交仍返回 `alreadySigned`。

仍需：多实例部署时把限流放到网关（当前是进程内计数）；异常峰值日志/告警。

## 7. 微信内打开的提示与真机

现状：签署页已按 UA 显示"在浏览器打开"提示，e2e 有断言；**真机未验证**。

目标：iOS Safari 与 Android Chrome 各走通一次完整签署；微信 → 浏览器跳转流程人工走通。

验收：截图归档；提示不影响桌面端。

## 8. 构建器与 CI

现状：Windows Turbopack 崩溃（`0xC0000005`）；Linux Node 26 的 build/dev 已验证可用。
构建产物用 `.next/BUILD_INFO.json` 的 `sourceHash` 证明来源（不依赖版本控制）。

目标：Linux CI 默认 Turbopack，跑完 e2e 后切换；Windows 保留 `--webpack`。

验收：Linux 上 build + e2e 60/60；`buildFresh=true`。

## 9. 可观测性与备份

现状（2026-11-23）：已有请求 ID（`x-request-id`）、`/api/health`、`/api/health/deep`（管理员）、
`/api/metrics`（进程内计数）、结构化 JSON 日志；仍没有集中日志、告警与定时备份。

目标：把 stdout JSON 接到日志系统（journald/Loki），对"签署失败率 / PDF 失败 / TSA 失败"
设阈值告警；Mongo 定时快照；恢复演练一次。

验收：能从快照恢复到一个空环境并跑通冒烟。

## 10. 已收敛的遗留（记录，不再作为待办）

- `/login` 单图案入口 → 已 302 到 `/admin/login`（旧接口要求管理员 cookie，原页面必然 401）。
- 管理入口的"第三道锁"疑问 → `/manager` 只用 `agreement_admin`；`ManagerAuthGate` 仅存于
  部分生成器布局，与本流程无关。
- 草稿校验顺序 → 已前移，失败不再消耗 `AGR` 编号。
- 模板字段 → 已支持 `{{partyA.legalRepresentative}}`。
- 管理 API → 已透传 `signers`（支持第三方签署人）。
- 管理手势摘要 → 已改为 HMAC（v2）+ 自动升级；无密钥时 fail closed。
- 打印 key → 已改为 10 分钟过期。
- 请求体 → 已改为流式截断（不信任 `Content-Length`）。
- 生产启动 → 已强制 `AGREEMENT_LINK_KEY`；`AGREEMENT_PUBLIC=1` 强制 https 公网基址；禁止 `RATE_LIMIT_DISABLED`。
- 签署页 → 不再显示其他签署人的 IP。
- 畸形 ObjectId → 返回 null/404，不再抛驱动错误。
- 管理会话 → 默认改为**浏览器会话级**（关浏览器需重画手势），勾选“记住这台设备”才保留 7 天；旧 v1 cookie 全部失效。
- 退出登录 → 清 cookie + `/manager` 带 `no-store`，回退按钮不再显示旧内容。
- 拒签流程 → 已实现：`DECLINED` + 理由（≤500 字），任一签署人拒绝即全员停签，可作废/重发。
- 证据包导出 → 已实现：ZIP = README + manifest（含逐文件 SHA-256）+ PDF + 签名图 + TSR；可用 openssl 离线复验。
- 证据事件链（2026-11-23）→ `SigningEvent` 每条事件 `prevHash` + `hash`，追加走独立事件队列（避免与签署锁死锁）；
  `/verify`、状态接口、证据包 manifest 返回 `events: {ok,complete,count,legacy}`；改事件 → `hash` 断，删中间事件 → `link` 断，
  旧记录（无 hash）报“完整（含 N 条旧记录）”，不误判为篡改。
- 证据 Ed25519 签名（2026-11-23）→ `signatureSig` / `completionSig` 入库存证；`/verify` 显示“服务端签名 有效（kid）”；
  公钥随证据包导出，私钥只留在环境变量。改库里的摘要 → 签名校验失败。
- 邀请链接密文 v2（2026-11-23）→ AES-GCM 用 AAD 绑定 `agreementId:signerId`（换记录必失败）；
  密文带 `kid`，`AGREEMENT_LINK_KEYS_PREVIOUS` 支持轮换双读；读取到 v1 时自动重封为 v2。
  v1 无 AAD，仍可读但不再签发。
- 管理入口第二因素 → 已实现：RFC 6238 TOTP（加密存储、防重放、±1 步容差），命令 `npm run init:totp`。
