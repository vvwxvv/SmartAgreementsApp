# 部署与回滚（当前版本）

> 最后核对：2026-11-23。适用当前源码（`sourceHash=ff43f8820956e9f7`，清理后 271 files）。
> 本项目不需要版本控制工具：构建来源用 `.next/BUILD_INFO.json` 的 `sourceHash` 证明。

## 1. 前置条件

- Linux 主机（Node 24/26），或 Windows（构建用 `--webpack`）。
- MongoDB **副本集**（Atlas 或自建 replica set）；单节点不受支持。
- 域名 + HTTPS；`AGREEMENT_BASE_URL` 必须是公开地址。
- 环境变量：`MONGODB_URL`、`MONGODB_DB`、`JWT_SECRET`、`ADMIN_SESSION_SECRET`、
  `AGREEMENT_INTEGRATION_SECRET`（≥24 字符）、`AGREEMENT_LINK_KEY`（≥32）、`CHROMIUM_BIN`（PDF）。
- 对外公开时设置 `AGREEMENT_PUBLIC=1`（启动会强制 https 公网基址）。
- 设置 `ADMIN_GATE_SECRET`（≥16，专用）：手势摘要改为 HMAC，旧摘要首次解锁自动升级。
- 可选设置 `ADMIN_TOTP_KEY`（≥16）：TOTP 密钥用 AES-256-GCM 加密落库。
- 启用 TOTP：`npm run init:totp [-- --mongo]`，按输出把密钥加进验证器 App。
- 会话策略：`ADMIN_SESSION_HOURS`（默认 12）、`ADMIN_REMEMBER_DAYS`（默认 7）。默认是会话 cookie，
  关浏览器后需要重新画手势；登录页勾“记住这台设备”才保留 7 天。
- **不要**设置 `ALLOW_LOCAL_IN_PRODUCTION`，也不要设置 `RATE_LIMIT_DISABLED`（生产启动会拒绝后者）。
- 启动自检（instrumentation）：缺 `JWT_SECRET`/`ADMIN_SESSION_SECRET`/`AGREEMENT_LINK_KEY`，或 `AGREEMENT_PUBLIC=1` 但基址不是 https 公网，会直接拒绝启动。

## 2. 构建与启动

```bash
npm ci
npm run build          # next build --webpack + stamp；Linux 也可用默认 Turbopack
npm prune --omit=dev
npm start              # prestart 检查 number_unique
```

记录三样东西：

- `.next/BUILD_ID`
- `.next/BUILD_INFO.json`（`sourceHash` / `files` / `builtAt` / `node` / `next`）
- `node -v`

`sourceHash` 是 `src/`、`packages/agreement/src/`、`prisma/`、`scripts/` 与根配置文件的
内容哈希。部署后想确认"跑的就是这份源码"，重算一次即可（`node -e` 调
`scripts/lib/source-hash.mjs` 的 `computeSourceHash()`），或跑一次 e2e 让它自动比对
（不一致会报 `buildFresh=false`）。

## 2b. Vercel 部署要点

`.env` 已填好除 MongoDB / 云服务之外的变量；在 Vercel 项目里直接粘贴 `.env` 的 `KEY=VALUE` 行即可。

必须确认：

- `DATA_SOURCE=auto`（有 `MONGODB_URL` 时自动走 Mongo）
- `MONGODB_URL` / `MONGODB_DB`（Atlas 连接串需允许 Vercel 出口；建议 `replicaSet` + `retryWrites`）
- `JWT_SECRET` / `ADMIN_SESSION_SECRET` / `ADMIN_GATE_SECRET` / `AGREEMENT_LINK_KEY`（每个 32+ 随机串）
- `AGREEMENT_EVIDENCE_PRIVATE_KEY` + `AGREEMENT_REQUIRE_EVIDENCE_SIG=1`
- `AGREEMENT_INTEGRATION_SECRET`（如果外部系统要查状态）
- `AGREEMENT_BASE_URL` 可保留 localhost：代码会忽略 localhost 并从请求 Host 派生公开地址；
  若绑定正式域名，建议改成 `https://sign.example.com` 并设 `AGREEMENT_PUBLIC=1`。

`.vercelignore` 已排除 `tests/`、`docs/`、`design/`、`data/`、`*.md`：这些不参与构建，也不需要上传。
`scripts/` 不能排除（`prestart` / `check-indexes` / 运维脚本）。

**PDF / TSA 注意**：Vercel 函数没有 Chromium 二进制，PDF 与证据包（内含 PDF）会失败。
需要 PDF 时把应用部署到容器/VM（装 `chrome-headless-shell` 并设 `CHROMIUM_BIN`），
或改成外部 PDF 服务。签署、核验、链接、事件链不受影响。

Vercel 上 `NEXT_PUBLIC_*` 在构建时内联；改这些值必须重新部署。

## 3. 索引（上线前必须执行一次）

需要的索引在 `scripts/lib/indexSpec.mjs`：

- `Agreement.number` 唯一（`number_unique`）
- `AgreementSigner(agreementId,email)` 唯一（`agreement_email_unique`）
- `AgreementSigner.accessTokenHash` 部分唯一（`accessTokenHash_partial`，仅字符串）
- 其余非唯一查询索引

生产路径：

```bash
npm run db:indexes:prod                          # dry-run：打印目标 host / 库 / 索引清单
npm run db:indexes:prod -- --apply --confirm=<dbName>
```

脚本读 `MONGODB_URL` / `MONGODB_DB`，拒绝 `DATA_SOURCE=local`；执行后校验唯一索引是否存在。
测试专用脚本 `db:indexes` / `db:push` 仍只接受 loopback `*_test`，不要混用。
请保存执行输出与索引清单。

完成后用 `prestart` 或 `node scripts/check-indexes.mjs` 验证；缺失 `number_unique` 会拒绝启动。

## 4. 冒烟清单

1. `/admin/login` 画两个手势 → `/manager` 200。
2. 建当事人（含法人代表）→ 建草稿（正文写 `{{partyA.legalRepresentative}}` 应能编译）→ 发送 → 拿到链接。
3. 浏览器打开 `/sign/<token>` → 手写签名 → 完成。
4. `/verify` 用证书编号查询 → `verified=true`。
5. 下载 PDF → 2 页，含签名与证明。
6. 未登录访问 `/manager` → 307；`/api/agreements` → 401。
7. `/sign/`、`/print/` 响应含 `X-Frame-Options: DENY`、`frame-ancestors 'none'`、`no-referrer`。
8. 限流生效：同一签名链接连续提交 21 次 → 第 21 次 `429`（带 `Retry-After`）。
9. 体积上限：向 `/api/manager/agreements` 发 1 MB 正文 → `413`。
10. 手势摘要方案：`GET /api/admin/gate` 返回 `"scheme":"v2"` 且 `"totp":true`（若已启用）。
11. `/api/health` 200 且带 `x-request-id`；`/api/health/deep` 200；`/api/metrics` 能读到计数。
11. 打印 key：直接访问 `/print/<id>?k=<10 分钟前的 key>` → 404。
12. 会话：不勾“记住”时响应 `Set-Cookie` 无 `Max-Age`；勾选后有 `Max-Age=604800`。退出后 `/manager` 立即 307。
10. 记录 `BUILD_ID`、`sourceHash`、冒烟时间。

## 4b. 健康检查与日志

```bash
curl -fsS https://<host>/api/health            # {"ok":true,"uptime":...}
curl -fsS -b <admin cookie> https://<host>/api/health/deep
curl -fsS -b <admin cookie> https://<host>/api/metrics
```

- 反向代理/编排只把 `/api/health` 当存活探针（不查库，避免拖垮数据库）。
- `/api/health/deep` 查库，适合发布后的一次性验证。
- 日志为单行 JSON：`{"ts","level","event","rid",...}`；`x-request-id` 同时返回给浏览器，
  用户报障时可直接对日志。
- 指标是进程内计数，重启归零；不要当长期统计用。多实例请从日志聚合。

## 6. 回滚

**优先只向前修复**，不以回滚作为默认路径。

- 回滚前先跑 `node scripts/check-rollback-safety.mjs`：`hashV=2` 且未完成/仍有待签人的合同会被判 `UNSAFE`；`DRAFT` 也不安全（旧代码会写 v1 哈希但保留 `hashV=2`）。
- 回滚窗口里旧代码用 `countThisYear` 发号，不更新 `Counter`；升级回来前必须：

```bash
node scripts/realign-counter.mjs          # dry-run
node scripts/realign-counter.mjs --apply  # $max，只升不降
```

- 已签署合同作废属于业务/法务决定，不是技术回滚选项。
- 回滚基线以迁移前快照为准；没有快照就不回滚。

## 7. 密钥与手势

- 轮换 `ADMIN_SESSION_SECRET` 会立刻注销所有管理会话。
- 管理手势存于 `AdminGate`（两个 sha256）；重置用 `node scripts/reset-admin-gate.mjs`。
- `AGREEMENT_LINK_KEY` 轮换（链接密文 v2）：
  - 已发出的链接按 `sha256(token)` 查表，**换密钥不会让在途链接失效**；受影响的是管理端"再次复制链接"能否解出明文。
  - 步骤：旧密钥填入 `AGREEMENT_LINK_KEYS_PREVIOUS`（逗号分隔，每项 ≥32）→ 新密钥写入 `AGREEMENT_LINK_KEY` → 重启。
  - 旧密文在首次 `getLinks` 时会以 v2（AAD=`agreementId:signerId`）自动重封；确认都能复制后可清空 `..._PREVIOUS`。
  - 不保留旧密钥直接换：在途链接仍可签，但管理端复制会落入 `failed` 列表（明确报错，不静默 404）。
  - v2 密文格式 `v2.<kid>.<iv>.<tag>.<ct>`；`kid` 为密钥 SHA-256 前 8 位，不含秘密。
- 变更 `JWT_SECRET` 会让打印链接的 HMAC 失效（PDF 需重新生成）。
- 证据签名密钥（Ed25519）：
  - 生成：`npm run init:evidence`（打印 env 行）或 `npm run init:evidence -- --write`（写 `.env`，自动备份）。
  - `AGREEMENT_EVIDENCE_PRIVATE_KEY` 只放服务端环境；公钥由 `kid` + `x` 导出（`/verify` 与证据包 `evidence-key.json`）。
  - 轮换：旧公钥加入 `AGREEMENT_EVIDENCE_PUBLIC_KEYS=<kid>:<x>`，再换私钥；否则旧记录会显示“无法验证（缺少对应公钥）”。
  - 私钥丢失：已签记录的签名仍可验证（有公钥），但无法再为**新**记录签名。
  - 强制要求（可选）：`AGREEMENT_REQUIRE_EVIDENCE_SIG=1`，缺失或无法解析时生产拒绝启动。
